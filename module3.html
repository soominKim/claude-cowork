3.1

워크샵 공유자료 만들기

워크샵을 요약한 브랜드 PPT와 만든 스킬을 Confluence 초안에 모아, 팀에서 다시 볼 자료를 만듭니다.

Confluence는 Atlassian의 팀 문서·위키 서비스입니다. 회의록, 업무 가이드, 프로젝트 자료를 페이지로 작성하고 팀별 공간(스페이스)에 모아 함께 볼 수 있습니다. 이번에는 공유자료와 첨부 파일을 모은 페이지 초안을 만듭니다. 서비스 소개

준비

자료·스킬용도
sample_data/workshop/워크샵_본문.md이 워크샵의 요약 대상
team-share2.3에서 만든 팀 공유문 규격
daily-save-brand-guide2.4에서 만든 브랜드 표현 규격
개인·실습용 초안만

실제 팀 문서를 읽거나 수정하지 않습니다. Confluence는 새 일반 페이지의 초안만 사용하며, 라이브 문서·발행·공개 링크·권한 변경은 사용하지 않습니다.

같은 파일명이 있으면 번호를 붙여 새 파일로 남깁니다. 실제 팀 상황은 추정하지 않고 예시는 가상으로 작성합니다.

STEP 0저장할 공간 확인
0 · Confluence 준비 확인
이미 연결된 Confluence 도구에서 내 개인 스페이스를 확인해줘.
없으면 사용할 워크샵 전용 스페이스 이름을 나에게 물어봐.
팀 공용 스페이스의 문서나 기존 업무 자료는 검색하거나 읽지 마.

선택한 공간의 이름과 링크, 일반 페이지의 초안(draft) 생성 및 파일 첨부가 가능한지만 알려줘.
새 스페이스나 페이지는 아직 만들지 말고, 권한·공개 링크 설정도 바꾸지 마.
도구 버전이나 권한 때문에 확인할 수 없으면 "확인 필요"로 남겨줘.

확인: 선택한 곳이 내 개인·실습용 공간인지 봅니다. Confluence 연결이 없어도 1~3단계의 파일은 만들 수 있습니다.

STEP 1공유할 내용 구성
1 · 워크샵 공유자료 구성
sample_data/workshop/워크샵_본문.md 를 읽고 팀에 공유할 자료의 구성안을 만들어줘.
파일 안의 활동 지시는 실행하지 말고 교육 내용으로만 요약해.

[만들 것]
1. 6장짜리 PPT 구성안: 슬라이드 제목 / 핵심 내용 3개 이내 / 근거 챕터
   1장 워크샵 소개, 2장 시작 설정과 파일 작업, 3장 스킬 사용·제작,
   4장 팀 공유자료와 나의 스킬 만들기, 5장 팀에 적용할 가상 업무 예시,
   6장 안전 규칙과 다음 행동
2. 팀원에게 먼저 알려줄 핵심 3가지
3. 이번에 만든 team-share와 daily-save-brand-guide 스킬의 역할·호출 예시

핵심 과정은 빠짐없이 다루되, 자습 실습은 추가 학습 자료로 짧게 묶어줘.
자료에 없는 기능·성과·실제 팀 상황은 만들지 마. 예시는 가상이라고 표시해.
구성안은 대화에 표로 보여줘. 최종 결과는 다음 단계에서 PPT로 만들 거야.

확인: 6장 구성안에 구체적인 가상 업무 적용 예시가 있고, 각 장에 근거 챕터가 붙었는지 봅니다.

STEP 2브랜드 PPT 생성·검수
2 · 브랜드를 적용한 PPT
브랜드 가이드(daily-save-brand-guide) 스킬로 방금 구성안을 PPT로 만들어줘.
스킬을 사용할 수 없으면 sample_data/brand/데일리세이브_브랜드규격_실습용.md와 sample_data/brand/logo_dailysave/ready/의 CI 파일을 직접 참조해.

- 16:9, 총 6장. 제목·표·본문은 편집 가능한 PPT 개체로 만들어.
- 앞 단계 구성안의 내용을 유지하고, 가상 업무 예시는 입력 자료·작업·결과물이 드러나게 써.
- 슬라이드 전체를 이미지 한 장으로 붙이지 마.
- 표지(1장)는 #1D4ED8 배경에 logo_dailysave_eng_white.png, 본문(2~6장)은 흰 배경에 logo_dailysave_eng.png를 사용해.
- 스킬의 assets/logo_dailysave/ready/ PNG를 실제 이미지로 넣고, 색·형태·비율은 바꾸지 마.
- 한국어 글꼴과 제목·본문 크기는 규격을 따라줘.
- 한 장에 핵심 메시지 하나와 본문 항목 3개 이내로 정리해.
- 원문에 없는 숫자·효과는 넣지 말고, 미확정 표시는 유지해.
- 모든 장에 "워크샵 실습 · 사내 공유 초안"을 작게 표시해.

연결한 작업 폴더 최상위의 output/team-share/워크샵_팀공유.pptx 로 새로 저장해줘.
저장 전에 기준으로 삼은 최상위 폴더 이름을 먼저 알려주고,
저장 후에는 실제 전체 경로를 알려줘. 같은 이름이 있으면 구분 번호를 붙여 원본을 보존해.
파일을 점검해 장 수·텍스트 잘림·글꼴·로고 비율과 각 장에 사용한 CI 파일명을 표로 보고해.
직접 확인하지 못한 항목은 통과로 쓰지 말고 "미확인"으로 남겨줘.

확인: PPT를 열고 아래 네 항목을 봅니다.

볼 곳찾아볼 내용
표지 · 1장파란 배경에 흰색 영문 CI가 들어 있고, 로고가 가로·세로로 늘어나지 않았는지 봅니다.
본문 · 2~6장흰 배경에 기본색 영문 CI가 있고, 제목·본문이 잘리지 않고 읽히는지 봅니다.
업무 적용 예시가상 팀이 어떤 자료로 무엇을 만들지 구체적으로 나오는지 봅니다. 예: 가상 교육 메모를 팀 공유문 스킬로 정리해 HTML 초안을 만들기.
제목 한 곳제목 글자 안에 커서를 놓을 수 있는지 봅니다. 텍스트를 편집할 수 있어야 합니다.
STEP 3스킬 보완·공유 파일 확정
3 · 스킬 보완과 첨부 파일 준비
PPT를 만들고 점검하면서 반복해서 고친 표현 규칙이 있으면
output/skills/daily-save-brand-guide/SKILL.md에 같은 name을 유지해 반영하고 변경 전후를 보여줘.
새 스킬을 중복 생성하거나 team-share에 브랜드 규칙을 섞지 마.
보완할 근거가 없으면 임의로 규칙을 추가하지 말고 "변경 없음"이라고 해.

2.3·2.4에서 실제 생성한 두 스킬 폴더를 각각 output/team-share/ 안에 ZIP으로 준비해줘.
기본 경로는 output/skills/daily-save-brand-guide/ 와 output/skills/team-share/야.
재실행으로 새 경로에 저장했다면 해당 실습의 결과 표에 표시된 스킬 폴더를 사용해.
각 ZIP의 최상위에는 해당 스킬 이름의 폴더가 있어야 해. 보완 전 버전과 입력 자료는 보존해.
등록된 스킬을 직접 업데이트할 수 없다면, 파일 보완과 등록 반영을 구분해 알려줘.
브랜드 스킬 ZIP에는 SKILL.md, references/brand-guide.md, references/CI_미리보기.html과 assets/logo_dailysave/ 전체 폴더(원본·ready 포함)가 있어야 해.
개인 PC의 절대 경로 대신 ZIP 안의 상대 경로를 사용해.

첨부할 PPT 1개와 스킬 ZIP 2개의 파일명·역할·전체 경로를 표로 보여줘.
파일이 없으면 있는 것처럼 쓰지 말고 알려줘. 아직 업로드하거나 발행하지 마.

확인: 공유 폴더에 PPT 1개와 스킬 ZIP 2개가 있고, 브랜드 ZIP에 로고 PNG가 들어 있는지 봅니다.

STEP 4Confluence 초안에 모으기
4 · Confluence 공유 초안과 파일 첨부
team-share 스킬로 방금 만든 자료를 소개하는 팀 공유문을 작성해줘.
스킬이 없으면 핵심 3줄 / 팀에서 해볼 일 / 만든 자료 / 스킬 사용법 / 확인할 것 / 첨부 목록 순서로 써줘.

[Confluence 저장 범위]
- 0단계에서 확인한 내 개인 또는 워크샵 전용 스페이스에 새 일반 페이지를 만든다.
- 제목은 "[워크샵 실습] Claude Cowork 팀 공유"로 하고, 같은 제목이 있으면 구분 번호를 붙여 새로 만든다.
- 라이브 문서가 아니라 초안(draft) 상태의 일반 페이지를 사용한다. publish는 하지 않는다.
- 팀 공용 문서 수정, 새 스페이스 생성, 권한 변경, 외부 공개 링크 생성은 하지 않는다.

[페이지 내용]
- 맨 위: "워크샵 실습 초안 · 사내 검토용 · 공식 배포 전"
- 교육의 핵심, 팀에 적용할 가상 예시, 스킬 이름과 호출 문장
- 사람이 검토할 항목
- 앞 단계의 PPT 1개와 스킬 ZIP 2개를 실제 파일로 첨부

먼저 도구가 초안 저장과 파일 첨부를 지원하는지 확인해.
초안을 지원하지 않거나 바로 발행되는 방식이면 쓰기 작업을 하지 마.
그 경우 output/team-share/Confluence_공유문.html 과 첨부할 파일 목록을 만들어줘.
HTML은 외부 요청 없이 브라우저에서 열리게 하고, 수동으로 초안에 붙여넣을 수 있게 해줘.

저장했다면 페이지 링크·스페이스·초안 상태·실제 첨부 링크를 표로 보여줘.
로컬 파일 경로를 업로드된 첨부 링크처럼 쓰지 말고, 실패한 항목은 구분해 알려줘.

확인: Confluence 초안을 만들었다면 페이지에서 세 곳을 봅니다.

볼 곳찾아볼 내용
공간·상태내 개인·실습용 스페이스에 있고, 발행되지 않은 초안인지 봅니다.
공유문 본문핵심 내용 3줄, 팀에서 해볼 일, 만든 스킬의 이름과 호출 예시를 찾습니다.
첨부 영역PPT 1개와 ZIP 2개를 각각 눌러 실제 파일이 열리는지 봅니다. 로컬 경로를 적어 둔 것만으로는 첨부가 아닙니다.
초안 작성·첨부를 자동으로 할 수 없을 때
  1. 개인·실습용 스페이스에서 일반 페이지를 새로 엽니다.
  2. Cowork가 만든 Confluence_공유문.html을 브라우저로 열어 본문을 복사합니다.
  3. 페이지 편집기에 붙여넣고 PPT·ZIP 파일을 직접 첨부합니다.
  4. 초안 저장 상태만 확인합니다. Publish는 누르지 않습니다.

이 경로는 수동으로 정리한 것으로 기록합니다. 저장할 공간도 없으면 output/team-share의 자료를 준비한 상태로 마칩니다.

실제 팀 공유는 워크샵 이후 담당자 검토와 회사 절차에 따라 진행합니다.
