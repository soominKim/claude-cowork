2.1

스킬이란 무엇인가

스킬은 반복해서 사용할 업무 절차와 작성 규칙을 저장한 지침서입니다.

SKILL.md 파일에 아래 내용을 적습니다. 필요한 양식·용어집·로고도 함께 묶을 수 있습니다.

구성역할
이름 · name목록에서 스킬을 찾고 요청할 때 쓰는 이름
설명 · description어떤 작업에서 이 스킬을 사용할지 안내
본문작업 순서·결과 형식·지켜야 할 규칙

등록한 스킬은 대화에서 이름을 지정해 사용할 수 있습니다. 공개된 스킬을 받아 쓰거나, 필요한 규칙으로 고쳐 나만의 스킬을 만들 수 있습니다.

internal-comms 스킬의 SKILL.md 파일 전문 보기

모든 스킬에는 SKILL.md 파일이 필요합니다. 이 파일은 두 부분으로 구성됩니다: Claude에게 스킬을 언제 사용할지 알려주는 --- 마커 사이의 YAML frontmatter와, 스킬이 실행될 때 Claude가 따르는 지침이 포함된 markdown 콘텐츠입니다. 디렉토리 이름(또는 frontmatter name을 설정한 경우 해당 값)이 입력하는 명령이 되고, description은 Claude가 스킬을 자동으로 로드할지 결정하는 데 도움이 됩니다.

internal-comms/SKILL.md
---
name: internal-comms
description: A set of resources to help me write all kinds of internal communications, using the formats that my company likes to use. Claude should use this skill whenever asked to write some sort of internal communications (status reports, leadership updates, 3P updates, company newsletters, FAQs, incident reports, project updates, etc.).
license: Complete terms in LICENSE.txt
---

## When to use this skill
To write internal communications, use this skill for:
- 3P updates (Progress, Plans, Problems)
- Company newsletters
- FAQ responses
- Status reports
- Leadership updates
- Project updates
- Incident reports

## How to use this skill

To write any internal communication:

1. **Identify the communication type** from the request
2. **Load the appropriate guideline file** from the `examples/` directory:
    - `examples/3p-updates.md` - For Progress/Plans/Problems team updates
    - `examples/company-newsletter.md` - For company-wide newsletters
    - `examples/faq-answers.md` - For answering frequently asked questions
    - `examples/general-comms.md` - For anything else that doesn't explicitly match one of the above
3. **Follow the specific instructions** in that file for formatting, tone, and content gathering

If the communication type doesn't match any existing guideline, ask for clarification or more context about the desired format.

3P updates, company newsletter, company comms, weekly update, faqs, common questions, updates, internal comms

프로젝트 또는 폴더에서 sample_data가 들어 있는 폴더를 연결합니다. 원본 스킬은 sample_data/skills/internal-comms/에 준비되어 있습니다.

1 · 주간 상태 보고를 사내 양식으로
internal-comms 스킬로 가상 "데일리세이브 운영팀"의 3P 주간 업데이트를 작성해줘.

[범위]
- 작성 기준: 2026-09-03, 읽는 사람: 팀 매니저

  sample_data/raw_meeting_notes.txt

[작성]
- 원본 3P 양식대로 Progress·Plans·Problems를 각각 1~3문장으로 써줘.

결과 영역여기서 볼 것이번 자료의 예시

예산 초안을 받은 것은 Progress에, 예산 승인이 남은 것은 Problems에 해당합니다.

3P 내용 예시

Progress: 자동적립·목표설정·리워드알림을 MVP로 확정했습니다. 주지표는 30일 리텐션, 가입자수는 보조지표입니다.

Plans: 개발 일정표는 9/8, 상표 대안과 채널별 예산안은 9/10까지 정리할 예정입니다. 데모데이 최종일은 9/11 회의에서 결정할 예정입니다.

Problems: 서비스명은 유사상표 검토가 남아 있고, 데모데이는 10월 첫주로 연기 제안 중입니다. 초기 프로모션 2.5억은 초안이며, 전사 예산 CSV와 프로젝트의 연결은 확인이 필요합니다.

[규칙]

- 업무 예시는 가상으로 작성한다. 실제 고객정보나 미공개 정보를 넣지 않는다.
- 메일·메신저 발송, Confluence 발행은 하지 않는다. 초안만 만든다.
- 원본을 수정·삭제하지 않고 output에 새 파일로 저장한다.
- 업무 내용 중 확인할 사항은 5번에만 모으고, 본문 뒤에 같은 목록을 반복하지 않는다.

[이번 작업의 저장 방식]
- 기존 파일은 수정·덮어쓰지 마. 임시 파일 정리를 포함해 파일·폴더를 삭제하지 마.
- output/skills/team-share/에 SKILL.md를 새로 만들어줘.
  폴더가 이미 있으면 output/skills/실습2/team-share/처럼 번호를 늘려 새 경로를 사용해.
- 원본 LICENSE.txt를 내용 변경 없이 함께 복사하고, SKILL.md의 license는 이 파일을 참조하게 해.
  본문에는 원본 internal-comms를 팀 공유문 규격으로 수정한 사본임을 한 줄로 남겨줘.
- 필요한 작성 규칙은 references/에 새로 작성해. 원본의 examples/는 복사하지 않아도 돼.

  다시 열어 SKILL.md·LICENSE.txt와 참조한 파일이 모두 들어 있고 읽히는지 확인해.

- 디스크에 임시 ZIP을 만들거나 이름을 바꾸는 압축 방식은 사용하지 마.

정상적으로 완료되면 변경된 규칙과 스킬 폴더·ZIP 경로만 표로 보여줘.
복사하지 않는 examples/나 해결된 제작 이력을 "확인 필요"로 덧붙이지 마.
sample_data가 보이지 않으면 파일 누락으로 판단하지 말고, 자료가 들어 있는 폴더 연결을 먼저 안내해.

# 카드뉴스 제작 가이드

## 1. 보편 제작 원칙

- 장르와 주제에 관계없이 모든 카드뉴스에 적용되는 규칙

### 원칙 1:
- 카드뉴스 표지가 조회수를 결정한다.
- 표지에서 사람들의 시선을 끌어야 하며 두번째 슬라이드로 넘어가도록 내용을 남겨야 한다.
- 카드뉴스는 탐색 피드에서 대부분 노출된다.

### 원칙 2:
- 떡상하는 카드뉴스의 구조는 다음과 같다.

Hook (표지) → 핵심 내용 → CTA (마무리)


- 스토리텔링, 공감요소는 중간에 채운다.
- 후킹요소와 CTA는 어떤 테마든 반드시 존재해야 한다.

### 원칙 3:
- 한 장에 전달하려는 메시지는 하나여야 한다.
- 불필요한 내용을 제거하고 가장 요약된 상태로 제공하는 것이 핵심.
- 텍스트와 시각 요소가 같은 메시지를 가리켜야 하며,
- 한 장에서 두 가지를 말하려 하면 아무것도 전달되지 않는다.

### 원칙 4 — 디자인 기본 규칙:
- 폰트: Pretendard / Noto Sans KR
- 여백: 균일하게 유지, 정렬 기준 고정
- 레이아웃: '4-4. 레이아웃 구조 패턴'을 참고해서 내용에 맞는 레이아웃 구조 최대 2개 이상 사용, 하단에 사용자 아이디 푸터 필수 배치

#### 4-1. 가독성 (Readability):
'보는' 것이 아니라 '읽히는' 디자인

- **위계 설정 (Typography Hierarchy)**: 제목 / 본문 / 태그·푸터의 폰트 크기와 굵기를 명확히 차별화. 제목은 본문보다 최소 1.5배 이상 크고 두꺼워야 시선이 자연스럽게 흐른다.
- **행간·자간**: 행간(`line-height`) 1.4~1.6배 유지. 본문 자간(`letter-spacing`)은 살짝 좁게(-0.02em) 설정하면 가독성이 상승한다.
- **대비 최적화**: 배경과 텍스트의 명도 차이를 확실하게. 밝은 배경 위에는 무거운 블랙보다 짙은 그레이(#111~#333)를 사용해 눈의 부담을 줄인다.

#### 4-2. 전체적인 조화 (Overall Harmony):
브랜드 정체성을 유지하는 일관성

- **톤앤매너 유지**: 메인 컬러와 서브 컬러의 사용 범위를 모든 슬라이드에 동일하게 적용. 강조 키워드는 항상 같은 컬러 계열을 사용해 독자가 본능적으로 중요한 정보임을 인지하게 한다.
- **여백의 일관성 (Safe Zone)**: 모든 슬라이드의 상하좌우 여백(Margin)을 고정값으로 유지. 슬라이드를 넘길 때 텍스트·로고 위치가 흔들리면 전문성이 떨어져 보인다.
- **UI 요소 통일**: 태그의 둥글기(border-radius), 화살표 아이콘 크기, 푸터 위치를 고정해 전체적인 시각적 리듬감을 부여한다.

#### 4-3. 구성요소 비율 (Component Ratio):
시각적 균형을 만드는 8:2 법칙

- **콘텐츠 vs 여백**: 텍스트·그래픽 요소는 슬라이드 면적의 70~80%를 넘지 않는다. 나머지 20~30%의 여백이 메인 메시지를 돋보이게 한다.
- **상중하 수직 배분**:
- 상단 15% — 태그 및 카테고리 (시각적 앵커)
- 중앙 70% — 메인 타이틀 및 핵심 본문 (정보 전달의 핵심)
- 하단 15% — 푸터 및 내비게이션 (브랜딩 및 행동 유도)
- **텍스트 밀도**: 한 문장은 최대 2줄을 넘지 않도록 나눈다. 문단 사이의 간격은 제목-본문 간격보다 넓게 배치해 시각적 숨통을 틔운다.

#### 4-4. 레이아웃 구조 패턴:
- 상단 태그 / 중앙 메인 카피 / 보조 카피 / 중앙 하이라이트 텍스트 박스 / 사용자 계정 푸터 및 화살표 아이콘
- 좌상단 태그 / 질문형 메인 카피 / 3단 인터페이스 그래픽 / 번호순 상세 설명 박스 / 사용자 계정 푸터 및 화살표 아이콘
- 좌상단 태그 / 단계별 메인 카피 / 보조 카피 / 아이콘+설명 리스트 / 하단 강조(Tip) 박스 / 사용자 계정 푸터 및 화살표 아이콘
- 좌상단 태그 / 좌정렬 메인 카피 / 보조 카피 / 저장 유도 배지 / 사용자 계정 푸터 및 화살표 아이콘
- 좌상단 태그 / 메인 카피 / 핵심 공식(텍스트) / 상황별 프롬프트 카드 2종 / 사용자 계정 푸터 및 화살표 아이콘
- 중앙 태그 / 중앙 정렬 메인 카피 / 보조 카피 / 알약형 CTA 버튼 / 하단 액션 아이콘(저장, 공유) / 사용자 계정 푸터
- 카테고리 태그 / 메인 카피 / 보조 카피 / 그래픽 요소 / 사용자 계정 푸터

#### 디자인 규칙 :
- 색상 정확도, 요소 간 간격 일관성, 내부 padding 균형

## 2. 스크립트 작성 규칙:

### 규칙 1 — 본문 텍스트 밀도 기준 :
각 슬라이드의 본문 텍스트는 반드시 아래 기준을 충족해야 한다.

- 리스트형 슬라이드: 항목당 1~2문장 분량의 설명 포함
(단순 키워드 나열 금지. 각 항목에 수치·이유·예시 중 하나 이상 포함)
- 서술형 슬라이드: 최소 3~4문장 분량의 본문 작성
- 숫자·통계가 있는 경우: 맥락 설명 1문장 반드시 추가
예) ❌ "매출 6,000억 원"
✅ "매출 6,000억 원 — 창업 9개월 만에 달성한 수치로,
시리즈 A 유치 없이 AI 도구만으로 운영한 결과"

### 규칙 2 — 원문 충실도 :
기사·원고를 기반으로 제작할 경우, 각 슬라이드의 본문은
원문에서 해당 슬라이드 주제와 관련된 핵심 정보를
빠짐없이 추출해 담아야 한다.
